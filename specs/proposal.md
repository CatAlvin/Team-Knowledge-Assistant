# 团队知识助手

## 目标与背景

工程团队的消息分散在多个频道，故障进展、行动项和操作指南难以统一查阅。项目将固定消息快照转为频道摘要、结构化任务、规则风险和有出处的知识回答。作者负责完整业务流程与接口交付。

## 范围

- TK-01：读取项目内消息 JSONL，验证字段，保留消息 ID 和时间。
- TK-02：按频道生成摘要；离线使用摘录，live 使用模型。
- TK-03：提取任务、负责人、到期日、优先级；输出必须符合 Pydantic 契约，错误不能静默变为空结果。
- TK-04：风险关键词按 high、medium 优先级匹配，每条消息最多一条提醒，跳过 #random。
- TK-05：对 Markdown 知识库执行 TF-IDF 检索，带来源和片段编号；无相关内容时拒答。
- TK-06：提供 CLI、REST 和 stdio MCP；digest 汇总全部能力。
- TK-07：默认 offline；配置与数据在项目内；健康检查与业务执行分离。

本期不包括实时 Slack 消息采集、后台任务队列、多租户、自动发消息或自动执行行动项。

## 成功标准

| 编号 | 可验证条件 |
| --- | --- |
| TK-AC01 | 样例数据可读取；缺少字段、重复 ID 或错误类型报错 |
| TK-AC02 | 已有频道返回摘要；不存在频道返回明确空状态 |
| TK-AC03 | 任务字段有类型与枚举校验；离线到期年份来自消息；模型输出畸形时报错 |
| TK-AC04 | high 优先，#random 不报风险，正常消息不触发 |
| TK-AC05 | 问答来源结构化，支持拒答与空知识库；更换知识库路径不会复用错误索引 |
| TK-AC06 | REST 参数越界返回 422，令牌错误返回 401，digest 与独立能力一致 |
| TK-AC07 | MCP 列举和调用成功；机器契约与运行时一致；单独复制项目可运行 |

## 约束

Python 3.12，FastAPI / Pydantic，官方 MCP SDK，本地 TF-IDF。样例消息是功能演示数据，不代表真实企业业务量。上线效果和真实模型准确率另行测量。

## 前端工作台

通过浏览器完成数据概览、记录筛选、任务或风险跟进、知识问答、来源阅读及简报导出。所有统计来自当前项目数据；交互与验收标准见 [workbench.md](workbench.md)。
